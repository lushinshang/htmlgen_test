2025 LLM Year in Review | karpathy

source: https://karpathy.bearblog.dev/year-in-review-2025/

1 · 重點整理

2025 年大型語言模型（LLM）迎來關鍵的「範式轉變」，其中「增強學習可驗證獎勵」（RLVR）成為主流訓練方式，顯著提升了模型的推理能力與成本效益。同時，LLM 的智能被重新理解為「鬼魂」而非「動物」，其能力呈現尖峰狀，並催生了如 Cursor 這類新的應用程式層，改變了 LLM 的生態系。

適合對象

AI 研究人員軟體工程師技術決策者AI 產品經理

重點收穫

深入解析 2025 年 LLM 在訓練方法、智能本質及應用架構上的三大範式轉變，揭示了 RLVR 的重要性及新型 LLM 應用程式的潛力。

2 · 主要內容

主要論點

2025 年大型語言模型（LLM）訓練進入「增強學習可驗證獎勵」（RLVR）新階段，取代過往主流的監督式微調與人類回饋增強學習。
背景：此論點位於文章開頭，點出 2025 年 LLM 發展在訓練方式上的核心轉變。它與後續討論 LLM 智能本質的論點形成對比，並為 RLVR 如何促成更複雜能力的發展奠定基礎。
證據：In 2025, Reinforcement Learning from Verifiable Rewards (RLVR) emerged as the de facto new major stage to add to this mix. By training LLMs against automatically verifiable rewards across a number of environments (e.g. think math/code puzzles), the LLMs spontaneously develop strategies that look like "reasoning" to humans - they learn to break down problem solving into intermediate calculations and they learn a number of problem solving strategies for going back and forth to figure things out
繁中補充：2025 年，『增強學習可驗證獎勵』（RLVR）成為了這個組合中一個事實上的新主要階段。透過在多個環境（例如數學/程式碼謎題）中，讓 LLM 針對自動可驗證的獎勵進行訓練，LLM 會自發發展出看似人類『推理』的策略——牠們學會將問題分解成中間計算，並學會了許多來回摸索以找出解決方案的策略。
為何重要：RLVR 的出現代表了 LLM 訓練方法論上的重大突破，從根本上改變了模型學習和展現智能的方式，是 2025 年 LLM 發展最重要的範式轉變之一，直接影響了模型的效能與成本效益。
高
LLM 智能的本質被重新理解為「召喚鬼魂」，而非「培育動物」，這影響了對其能力與限制的認知。
背景：此論點承接 RLVR 的訓練方法，深入探討其對 LLM 智能本質理解帶來的影響。它與「增強學習可驗證獎勵」的訓練方式相互呼應，並為後續探討新應用程式層的發展提供理論基礎。
證據：We're not "evolving/growing animals", we are "summoning ghosts". Everything about the LLM stack is different (neural architecture, training data, training algorithms, and especially optimization pressure) so it should be no surprise that we are getting very different entities in the intelligence space, which are inappropriate to think about through an animal lens.
繁中補充：我們不是在『演化/培育動物』，而是在『召喚鬼魂』。LLM 的堆疊（神經架構、訓練資料、訓練演算法，尤其是最佳化壓力）的一切都不同，所以我們在智能領域得到非常不同的實體，用動物的視角來思考牠們是不恰當的，這點並不令人意外。
為何重要：將 LLM 智能比喻為「鬼魂」而非「動物」，提供了一個更貼切的比喻來理解其非線性的、爆發式的學習特性，以及與傳統生物智能的差異，這有助於避免誤用和誤解，並引導更適合的應用開發。
高
「Cursor」這類新興應用程式層的出現，展示了 LLM 應用程式的組織化與專業化趨勢。
背景：此論點聚焦於 LLM 的應用層面，以 Cursor 為例，說明了 LLM 如何從單純的工具轉變為建構更複雜、特定領域應用程式的基礎。它與前述的訓練方式和智能本質探討，構成了 LLM 發展的完整圖像。
證據：What I find most notable about Cursor (other than its meteoric rise this year) is that it convincingly revealed a new layer of an "LLM app" - people started to talk about "Cursor for X". As I highlighted in my Y Combinator talk this year ( transcript and video ), LLM apps like Cursor bundle and orchestrate LLM calls for specific verticals: They do the "context engineering" They orchestrate multiple LLM calls under the hood strung into increasingly more complex DAGs, carefully balancing performance and cost tradeoffs. They provide an application-specific GUI for the human in the loop
繁中補充：我發現 Cursor（除了今年它的飛速崛起之外）最引人注目的是，它令人信服地揭示了『LLM 應用程式』的新層次——人們開始談論『各行各業的 Cursor』。正如我在今年的 Y Combinator 演講中所強調的，像 Cursor 這樣的 LLM 應用程式會為特定行業捆綁和組織 LLM 呼叫：牠們進行『上下文工程』，在底層編排多個 LLM 呼叫，串聯成越來越複雜的有向無環圖（DAGs），仔細平衡效能與成本考量，並為人機互動提供特定應用程式的 GUI。
為何重要：Cursor 代表了 LLM 應用程式發展的一個重要方向，顯示了將 LLM 整合進特定工作流程，並提供專業化介面的價值，這擴展了 LLM 的實用性，並預示了未來應用程式的架構演變。
高
Anthropic 的 Claude Code (CC) 改變了 AI 的互動模式，從單純的網站服務轉變為「住在」使用者電腦中的「小精靈」。
背景：此論點作為文章中對 LLM 應用與互動方式的具體案例。它呼應了前述「鬼魂」的智能比喻，並強調了 AI 服務從雲端延伸到使用者本地端互動模式的轉變。
證據：Anthropic got this order of precedence correct and packaged CC into a delightful, minimal CLI form factor that changed what AI looks like - it's not just a website you go to like Google, it's a little spirit/ghost that "lives" on your computer. This is a new, distinct paradigm of interaction with an AI.
繁中補充：Anthropic 掌握了這種優先順序，並將 CC 包裝成一個令人愉悅、簡潔的命令列介面（CLI）形式，改變了 AI 的樣貌——它不再只是像 Google 那樣一個你會上去的網站，而是一個『住』在你電腦裡的小精靈／鬼魂。這是一種與 AI 互動的全新、獨特的範式。
為何重要：Claude Code (CC) 的案例突顯了 AI 介面和部署模式的演進，從遠端雲端服務轉變為更貼近使用者、可嵌入本地系統的互動方式，這對使用者體驗和 AI 的普及性有著重要影響。
中
「Vibe coding」展現了 LLM 在英語自然語言介面下，讓非專業人士也能進行複雜程式開發的可能性。
背景：此論點探討了 LLM 在程式開發領域的變革，直接關聯到 LLM 能力的提升和應用的普及化。它呼應了「鬼魂」智能的某些應用面向，並與「Cursor」這類應用程式層的發展有潛在的協同作用。
證據：2025 is the year that AI crossed a capability threshold necessary to build all kinds of impressive programs simply via English, forgetting that the code even exists. Amusingly, I coined the term "vibe coding" in this shower of thoughts tweet totally oblivious to how far it would go :). With vibe coding, programming is not strictly reserved for highly trained professionals, it is something anyone can do.
繁中補充：2025 年是 AI 跨越了必要能力門檻的一年，能夠僅透過英語就能夠建構各種令人印象深刻的程式，甚至忘記程式碼的存在。有趣的是，我在這則思緒迸發的推文中創造了『Vibe Coding』這個詞，當時完全沒意識到它會發展到什麼程度。透過 Vibe Coding，程式設計不再僅限於訓練有素的專業人士，而是任何人都可以做的事。
為何重要：Vibe coding 的概念驗證了 LLM 在降低程式開發門檻方面的潛力，實現了技術民主化的願景，這對軟體開發產業和個人創造力都將產生深遠影響。
中
未來 LLM 的使用者介面（UIUX）將從目前的文字對話，朝向更符合人類視覺化和空間化偏好的圖像、動畫、網頁應用等多媒體格式發展。
背景：此論點為文章的結語部分，對 LLM 的未來發展方向進行展望，特別是在使用者互動介面（UIUX）的革新。它與前述的「鬼魂」智能概念相呼應，強調了 AI 應如何更符合人性。
證據：In particular, in terms of the UIUX, "chatting" with LLMs is a bit like issuing commands to a computer console in the 1980s. Text is the raw/favored data representation for computers (and LLMs), but it is not the favored format for people, especially at the input. People actually dislike reading text - it is slow and effortful. Instead, people love to consume information visually and spatially and this is why the GUI has been invented in traditional computing. In the same way, LLMs should speak to us in our favored format - in images, infographics, slides, whiteboards, animations/videos, web apps, etc.
繁中補充：特別是在 UIUX 方面，與 LLM 『聊天』有點像在 1980 年向電腦主控台發出指令。文字是電腦（和 LLM）的原始/偏好資料表示，但它不是人們的偏好格式，尤其是在輸入端。人們其實不喜歡閱讀文字——這又慢又費力。取而代之的是，人們喜歡視覺化和空間化地消費資訊，這也是為何傳統運算中 GUI 被發明出來的原因。同樣地，LLM 應該以我們偏好的格式與我們溝通——以圖像、資訊圖表、投影片、白板、動畫/影片、網頁應用程式等形式。
為何重要：此論點指出了目前 LLM 互動模式的局限性，並預測了未來更自然、更直觀的人機互動方式，這對於提升 LLM 的易用性和推廣普及至關重要，也為相關產品開發指明了方向。
中

思考脈絡

作者試圖釐清 2025 年大型語言模型（LLM）發展中的關鍵「範式轉變」，探討這些轉變如何改變了 LLM 的訓練方式、智能的本質以及應用程式的架構。

關鍵轉折

  • 作者選擇從「增強學習可驗證獎勵」（RLVR）、「智能的形狀」（鬼魂 vs. 動物）和「新的應用程式層」（Cursor）這三個角度來分析，因為它們代表了 2025 年 LLM 領域最顯著且具概念性的突破，足以影響整個領域的發展軌跡。

重要案例

  • 「增強學習可驗證獎勵」（RLVR）的出現，取代了過去的主流訓練方式，透過自動可驗證的獎勵來訓練 LLM，使其能發展出類似「推理」的策略，並大幅提升了能力與成本效益。

3 · 重要問題

核心問題

  • 2025年大型語言模型（LLM）發展中的核心範式轉變為何？
  • 這些範式轉變如何影響LLM的訓練方式、智能的本質以及應用程式的架構？

延伸思考

  • RLVR是否會成為未來LLM訓練的標準，或是僅為特定類型的任務有效？
  • 「智能的形狀」比喻（鬼魂vs.動物）對於我們理解和評估LLM的潛在局限性有何具體啟示？
  • Cursor所代表的「新的應用程式層」將如何進一步重塑LLM與使用者互動的方式？
  • 隨著LLM能力透過RLVR不斷提升，我們是否會看到更具體、更可控的AI智能形式出現？
  • Benchmarks在RLVR時代的有效性受到挑戰，未來應如何設計和衡量LLM的真實能力？

不同觀點

RLVR 與 RLHF 的根本性差異及對 LLM 能力的影響

論點：RLVR 是一種根本性的改變，能讓 LLM 發展出類似「推理」的能力，並帶來更高的效率，這與基於人類回饋的 RLHF 不同。

反方：雖然 RLVR 帶來了效率提升和類似推理的表現，但它是否真正實現了「推理」的本質，抑或是另一種形式的模式匹配或優化？RLHF 在特定場景下是否仍有不可替代的價值？

證據需求：對 RLVR 和 RLHF 訓練出的模型的認知能力進行更深入的比較研究，包括在複雜、開放式任務上的表現，以及對其決策過程的可解釋性分析。需要驗證 RLVR 是否能處理 RLHF 難以處理的、需要長期規劃和抽象思維的問題。

LLM 智慧的「形狀」：從「動物」到「鬼魂」的隱喻

論點：LLM 的智慧更像是「鬼魂」，其特徵與人類基於生存演化的「動物」智慧模型截然不同，表現出「鋸齒狀」的智能特徵。

反方：「鬼魂」的隱喻是否過於簡化或帶有潛在的誤導性？這種非演化論的視角，是否忽略了 LLM 在模仿人類學習過程中的某些共性？「鋸齒狀」智能的說法，是否掩蓋了 LLM 在某些領域的穩定性和持續進步？

證據需求：需要更多對 LLM 內在工作機制的研究，以科學的語言描述其智能的「形狀」和特性，而不僅僅依賴於隱喻。需要對比人類智能和 LLM 智能在不同認知任務上的根本差異和共性，並探討是否能用統一的框架來理解不同類型的智能。

基準測試（Benchmark）在 RLVR 時代的有效性與可信度

論點：在 RLVR 時代，基準測試的可信度嚴重下降，因為它們很容易被 RLVR 或合成數據生成技術所「攻破」，導致「在測試集上訓練」成為一種新興的藝術。

反方：雖然存在被攻破的風險，但嚴謹設計的基準測試仍然是評估 LLM 進步的重要手段。是否可以設計出更具魯棒性、更難以被攻破的基準測試，或者結合其他評估方法來彌補其不足？

證據需求：需要開發新的、更難被「規避」的評估方法和基準測試，例如動態生成、對抗性測試或基於真實世界任務的持續評估。同時，需要深入研究現有基準測試被攻破的機制，並提出相應的防禦策略。

4 · 精選語錄

“Reinforcement Learning from Verifiable Rewards (RLVR) emerged as the de facto new major stage to add to this mix.”

繁中補充：「透過可驗證獎勵進行的強化學習」（RLVR）成為了這個組合中，事實上是新的主要階段。
這是作者在描述 2025 年 LLM 發展中的一個重要轉變，相較於過去的預訓練、監督式微調和人類回饋強化學習，RLVR 是一種新的訓練方式。
位置：1. Reinforcement Learning from Verifiable Rewards (RLVR) - 第二段
說服力：0.90
說服力計算：0.90 = 0.40*0.93（可驗證性） + 0.35*0.90（脈絡貼合度） + 0.25*0.85（表述清晰度）

5 · 行動建議

重要發現

  • 2025 年 LLM 發展的核心範式轉變在於訓練方法的革新，特別是「增強學習可驗證獎勵」（RLVR）的崛起，它使得 LLM 能夠發展出更接近「推理」的能力，並大幅提升了效能與成本效益。
  • LLM 的智能特性不再是線性的、類比人類的「動物」式成長，而是呈現「鬼魂」般的、高度專精且具備「鋸齒狀」特徵的智能，在特定領域表現卓越，但在其他方面則顯得相對薄弱。
  • 過往的基準測試（benchmarks）在 RLVR 驅動下，已難以準確衡量 LLM 的真實能力，因為 LLM 可以利用驗證機制「訓練於測試集」，導致測試分數虛高，而實際應用中的魯棒性仍有待觀察。
  • 「Cursor」為代表的新一代 LLM 應用程式，不再僅僅是單純的 API 調用，而是能進行「上下文工程」和編排複雜的 LLM 呼叫鏈，形成「有向無環圖」（DAG），在效能與成本之間取得精妙平衡，展現了應用程式層的全新架構。
  • LLM 的「思考時間」或「推理步驟」成為了一個可控的參數，透過增加計算量來提升 LLM 的能力，這為模型性能優化開闢了新的維度，也意味著推理複雜度將成為未來 LLM 應用中的關鍵考量。

實際做法

技術長/研發負責人

評估並試點導入 RLVR 訓練流程，專注於具備可驗證獎勵機制的任務（如程式碼生成、數學推理、資料分析）。

RLVR 是 2025 年最關鍵的範式轉變，直接影響 LLM 的核心能力和成本效益。搶先採用 RLVR，能讓團隊快速掌握新型態的訓練方法，並在關鍵能力上取得領先，避免落後於競爭對手。

產品經理

重新審視現有產品的 LLM 應用架構，思考如何將 LLM 呼叫組合成更複雜的 DAG，以實現類似 Cursor 的「上下文工程」和垂直領域的深度整合。

Cursor 的成功表明了 LLM 應用程式正從單純的接口轉向更複雜的協調者。盡早規劃產品在這一新架構下的發展，能為未來產品的差異化和競爭力打下基礎，抓住應用層的發展機遇。

AI 研究員/架構師

投入資源研究 LLM 智能的「鋸齒狀」特性，理解其優勢與劣勢，並開發相應的評估方法，避免過度依賴傳統基準測試，轉而關注實際應用場景下的魯棒性和可靠性。

理解 LLM 智能的「鬼魂」模型和「鋸齒狀」表現，是有效利用 LLM 並避免誤判的關鍵。開發新的評估方法，能更準確地衡量模型在真實世界中的表現，為產品決策提供可靠依據。

產品經理/業務發展

探索利用 LLM 的「思考時間」和推理能力，設計能夠執行更複雜、多步驟任務的應用程式，並將其作為產品的核心賣點。

「思考時間」成為可控的性能調優參數，為開發需要深度推理和規劃的應用提供了可能。這將是區別於簡單 Prompt-Response 互動的新型態應用，能滿足更複雜的客戶需求。

資料科學家/工程師

建立一個系統性的「可驗證獎勵」生成和評估框架，並將其整合到現有的 LLM 訓練流水線中，確保訓練過程的數據品質和獎勵機制的有效性。

RLVR 的有效性高度依賴於可驗證獎勵機制的設計。建立一個穩健的框架，能夠確保模型獲得的獎勵是客觀且有意義的，進而提升訓練效果，為長期持續的模型優化奠定基礎。
